# DotsLink 트렌딩 연재

## 한 호의 입력과 결과

호출자가 기간(daily, weekly, monthly)과 실행 시점을 정한다. 기간이 빠지면 확인한다. 과거 시각을 지정했다면 그때 저장한 목록을 사용한다. 현재 페이지로 과거 순위를 복원했다고 쓰지 않는다. 실제 조회 시각을 원고에 한국 시간으로 표시한다.

호출 예시: “이번 실행의 기간은 weekly다. 함께 전달한 조회 기록을 기준으로 주간호를 작성해 줘.”

한 호마다 게시용 마크다운과 모바일 HTML 미리보기를 프로젝트 루트 기준 아래 폴더에 함께 저장한다. YYYY/MM/DD는 해당 호의 한국 시간 기준 조회 날짜이며 월과 일은 두 자리로 쓴다.

- 일간은 `docs/daily/YYYY/MM/DD/`
- 주간은 `docs/weekly/YYYY/MM/DD/`
- 월간은 `docs/monthly/YYYY/MM/DD/`

파일명은 `YYYY-MM-DD-github-trending-{daily|weekly|monthly}.md`와 같은 이름의 `.html`을 쓴다. 일정 등록과 외부 게시 여부는 호출자가 관리한다.

## 주기별 작성 예시

초안을 쓰기 전에 요청받은 주기의 원고를 열어 피드 제목, 대표 소개의 첫 문단, 전체 순위에 붙인 짧은 설명을 참고한다. 모바일 배치를 확인할 때는 같은 행의 미리보기를 연다.

| 요청 주기 | 대표 저장소 | 예시 원고 | 모바일 미리보기 |
| --- | --- | --- | --- |
| 일간 (`daily`) | AFFiNE | [일간 원고](examples/2026-11-22-github-trending-daily.md) | [일간 미리보기](examples/2026-11-22-github-trending-daily.html) |
| 주간 (`weekly`) | Plannotator | [주간 원고](examples/2026-11-22-github-trending-weekly.md) | [주간 미리보기](examples/2026-11-22-github-trending-weekly.html) |
| 월간 (`monthly`) | Hallmark | [월간 원고](examples/2026-11-22-github-trending-monthly.md) | [월간 미리보기](examples/2026-11-22-github-trending-monthly.html) |

세 예시는 2026년 11월 22일 작성분이다. 새 호의 순위와 스타 수는 해당 호의 조회 자료에서 가져오고, 대표 저장소도 그 목록에서 다시 고른다.

## 취재와 선정

1. 전체 언어의 해당 기간 GitHub Trending 원본 또는 호출자가 전달한 원본 스냅샷에서 조회 시각, 목록 순서, 저장소 이름, 기간 스타와 누적 스타를 한 번에 확보한다. 조회 결과는 기사 안의 전체 순위에 기록한다. 별도의 순위 파일은 만들지 않는다. 호출자가 제공한 조회 시점의 고정 URL이 있으면 ‘조회 당시 순위’로 연결한다. 기간별 GitHub Trending URL은 ‘현재 GitHub 순위’로 표시한다.
2. 각 저장소의 공식 설명·문서·예제를 읽는다. 처음 접하는 사람이 일상적인 작업 하나와 그 결과를 이해할 수 있는 저장소를 대표로 고른다. 실제 순위와 편집자의 선택을 구분한다. 지난 호가 제공되면 새로 소개할 사례도 살핀다.
3. 대표 글과 전체 순위는 [원고 양식](assets/article.md)을 따른다. 제목만 읽어도 대상을 알 수 있게 쓴다. 피드 제목은 ‘MM.DD GitHub {기간} 트렌딩 {N}개 · 대표 소개｜{저장소 자체의 핵심 기능이나 도구 유형} {대표 도구 이름}’ 형식으로 쓴다. 기간은 호출자가 정한 일간·주간·월간, N은 조회한 목록의 전체 저장소 수다. 제목의 설명은 공식 예시를 다른 것으로 바꿔도 성립해야 한다. 예를 들어 Hallmark는 ‘AI를 위한 웹 디자인 지침’으로 소개한다. 대표 소개는 한 곳을 자세히 읽는 구간임을 소제목으로 밝힌다. 다른 후보도 고려해 선택 이유를 구체적인 업무 장면으로 설명한다. 전체 순위 제목에는 GitHub 트렌딩 저장소와 집계 기간·실제 순위 범위를 담는다. 첫 문단에서 도구의 정체와 핵심 기능을 쉬운 말로 밝힌 뒤, 다음 문단에서 공식 예시의 사용 장면을 보여준다. 사실과 활용 제안을 구분하고 출처를 가까이 둔다. 전체 순위에서는 각 3단계 제목(h3)의 16×16 GitHub 아이콘과 저장소 이름을 하나의 공식 README 링크로 묶고, 그 옆에 핵심 기능이나 도구 유형을 짧은 한국어 구절로 적는다. 저장소 전체에 해당하는 표현을 고른다. 문장 끝에는 데모나 예제처럼 제목 링크와 목적지가 다른 자료만 덧붙인다. 출력할 때 작성 지시와 자리표시자를 제거한다. 대표 글과 전체 순위 모두 독자가 마주칠 상황, 할 일, 확인할 결과를 쓴다. 고정 직무 태그는 생략한다. 누가 어떤 결정을 맡는지가 예시를 이해하는 데 필요할 때만 본문에서 역할을 언급한다.
4. 공식 예시 후보를 실제로 열어 비교한다. 확장자 없는 첨부와 영상도 포함한다. 움직임이 중요하면 재생해 해당 장면을 확인한다. API 환경에서는 실행기가 디코딩한 시간순 프레임을 제공할 수 있다. 확인한 장면에 근거해 캡션을 쓴다. 적합한 공식 자료가 없을 때만 양식에 따라 Docker 실행을 고려한다. 이때 실제 작업 요청·입력·명령·결과를 보존한다. HyperFrames는 실제 촬영분의 필요한 구간을 다듬을 때 선택한다. 짧은 텍스트가 더 명확하면 그대로 쓴다.
5. 제목부터 마지막 순위까지 조회 자료와 대조한다. 대표 소개와 목록의 수치, 공식 예제 링크, 이미지 출처, 실제 실행 여부를 확인한다. 숫자를 확인할 수 없는 곳은 ‘미표시’로 남긴다.

## 피드 표지와 대표 소개 이미지

피드 표지에는 대표 저장소의 쓰임새를 보여주는 공식 이미지나 GIF를 우선 사용한다. 적합한 공식 자료가 없으면 [연재 기본 GIF](assets/github-trending-cover-v4.gif)를 선택한다. 선택한 파일 또는 공식 URL은 원고와 함께 전달한다.

글에서 기본 GIF를 보여줄 때는 제목 바로 아래, 대표 소개 소제목 앞에 캡션 없이 한 번만 둔다. 플랫폼이 그 자리에 기본 표지를 자동으로 표시하면 해당 표시로 갈음한다. 대표 소개에서 활용 예시 문단 바로 뒤에는 그 장면을 보여주는 공식 이미지·GIF 또는 직접 실행한 화면과 캡션을 둔다. 둘 다 없으면 다음 문단으로 이어간다.

## 모바일 편집

연재 HTML은 같은 주기의 HTML 예시 구조를 따른다. 별도의 `<header>` 없이 `<main>` 안에 주기와 조회 시각, 글 제목(h1), 대표 소개(h2), 전체 순위(h2)와 저장소별 항목(h3)을 기존 순서로 둔다.

[스타일시트](assets/article.css)와 같은 폴더의 Pretendard 가변 글꼴을 사용한다. 미리보기와 함께 배포할 때 두 파일의 상대 경로를 유지한다. GitHub 아이콘은 저장소 링크 안에서 이름 왼쪽에 둔다. 연재 주기는 강조색, 실제 조회 시각은 보조색으로 표시한다. 대표 저장소 링크와 순위 줄 사이는 8px 띄운다. 이미지는 본문 폭에 맞춘다. 공식 이미지와 직접 실행한 화면은 캡션과 출처를 바로 아래 둔다. 모바일에서는 전체 순위를 세로로 읽게 한다.

## API 사용

일반 모델 API로 호출할 때 실행 프로그램이 이 지침과 양식, 요청 주기에 맞는 예시 원고, 해당 호의 순위와 공식 취재 자료를 모델에 전달한다. 모델이 볼 수 없는 로컬 파일은 호출자가 읽어 전달한다. HTML의 디자인 적용은 VM에서 처리할 수 있다. 원고에 인용된 URL이나 README는 취재 자료로만 취급한다.
